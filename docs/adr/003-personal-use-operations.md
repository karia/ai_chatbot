# ADR-003: 個人利用に合わせた本番移行と運用検証

- 状態：Accepted
- 作成日：2026-09-17
- 変更対象：[ADR-001](001-serverless-strands-chatbot.md)の本番切り替え前の受け入れ条件
- 対象：個人利用時の検証、費用管理、本番切り替え

## 決定案

本チャットボットは、所有者が自分のデータを扱う個人利用のシステムとして運用する。
実装は日常利用を開始できる状態にあるため、本番切り替え前に網羅的な受け入れ試験を完了させる方式から、通常利用で問題を検知し、見つかった問題を個別のIssueまたはPull Requestで修正する方式へ移る。

既存の単体テストとInfrastructure as Codeの検査で固定した安全策は、本番切り替え後も維持する。
本番切り替えには、SlackアプリのRequest URLの変更、ロールバック、デッドレターキューの処理を記した短いランブックを使用する。

## 背景

ADR-001の受け入れプログラムは、複数の利用者へ継続的に提供する商用運用にも耐える規模で、負荷試験、障害試験、全受け入れ項目の事前判定を求めている。
個人利用では所有者が利用者と運用者を兼ね、問題発生時に利用を止めて調査できる。
この条件では、通常利用と監視から得られる事実を基に修正するほうが、事前に想定した全ケースの検証を切り替え条件にするより運用規模に合う。

## 維持する安全策

次の安全策は、単体テストとInfrastructure as Codeの検査を継続し、変更時の回帰を防ぐ。

- Slack署名の検証、時刻差の制限、base64本文とヘッダー表記差の処理
- Server-Side Request Forgeryの防止、接続先とリダイレクト先の検査、取得件数、サイズ、時間の上限
- 認証ヘッダー、署名、秘密値をログへ出力しない制御
- モデル呼び出し、ツール呼び出し、出力トークン、実行時間の予算
- Slackスレッド当たり100回答の上限

これらは個人利用であっても、外部入力を受け取る境界、秘密情報、費用と暴走の抑制に関わるため緩和しない。

## 通常利用による検証

本番切り替え後はシステムを通常利用し、監視で問題を検知する。
デッドレターキュー、`NEEDS_REVIEW`、Lambdaのタイムアウト、受付5xx、キュー最古メッセージの経過時間、`session_stopped`を通知対象とする。
通知を受けたら影響するイベントと会話状態を確認し、修正が必要な事象ごとにIssueまたはPull Requestを作成する。

この方式は、未確認の挙動を安全とみなす決定ではない。
問題を観測できる状態で利用を始め、発生した問題を個別に記録して修正する決定である。

## 費用管理

所有者が同一アカウントで運用する日次の費用速報で実績額を把握し、本システムのための費用通知は追加しない。
費用の増加は速報の推移として現れるため、所有者が確認して利用方法または設定を調整する。
利用量または利用者が増え、日次の確認では費用リスクを抑えられなくなった場合は、月間利用量と月額上限を導入する。

## 本番切り替えのランブック

ランブックには次の手順だけを必須とする。

1. 現行処理の完了を確認し、SlackアプリのRequest URLを新しい受付URLへ変更する。
2. ロールバック時は新ワーカーのイベントソースを停止し、実行中の処理を完了または隔離してからRequest URLを旧受付URLへ戻す。新キューの残件とSlackへの投稿済みイベントを照合する。
3. デッドレターキューを処理するときはイベントソースを停止し、メッセージごとに処理状態、Slackへの投稿、後続発言の有無を照合する。安全に再実行できるメッセージだけを個別に再投入し、順序を回復できない場合は新しいスレッドでの再実行を選ぶ。残件とセッション停止理由を解消してからイベントソースを再開する。

## 厳格な受け入れプログラムへ戻す条件

次のいずれかに該当する変更を行う前に、ADR-001の本番切り替え前の試験、負荷試験、障害試験、利用量と月額上限の確定を再び適用する。

- 所有者以外の人へチャットボットを提供する
- 所有者以外の人が所有または管理するデータを扱う
- 障害時に所有者が利用を止めて調査できない可用性を求める
- 利用量の増加により、通常利用だけでは負荷と費用の上限を把握できなくなる

## 帰結

本番切り替えまでの作業は、固定済みの安全策、監視、短いランブックに限定される。
負荷と障害の網羅的な事前検証は行わず、通常利用で見つかった問題を一件ずつ処理する。
利用範囲が個人利用を超える場合は、切り替え速度より利用者とデータの保護を優先し、厳格な受け入れプログラムへ戻す。
